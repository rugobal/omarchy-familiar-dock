Plugin extensions: `favorites` (run 1/2, AppModel/Config/SystemDefaults), `hide-omarchy-dock` (run 1/2, DockLifecycle), `theme-bg-color` and `icon-contrast-outline` (run 2, ThemeBackground/IconColors), `show-scratchpad-windows` (AppModel; off by default, hides windows on Hyprland special workspaces except `special:minimized`), `animate-appicon-hover-macos` (Hover/Taskbar/Panel; off by default, macOS-style Plank: icons make the room they grow by, Show Apps joins the row when it touches the taskbar, and a fit-to-icons panel widens), `show-apps-hotkey` (AppsKey/Chord/HotkeyField/Cleanup; Overview and Position, default Omarchy's Super+Alt+Space Apps key, recorded by pressing a combination while Hyprland's bindings are paused in an empty submap; binds the key to Show Applications inside the running compositor while the plugin runs, replaces only Omarchy's own default binding on it, leaves the key alone when the user's own Hyprland files bind it or another binding uses it in any submap, reloads only once per change of key, and reloads Hyprland once on disable to restore the configured binding; no Hyprland file is written), `show-apps-click` (DrawerClick/DrawerClickField; Overview and Position, default open the drawer; a left click on Show Apps opens the drawer, an app, a command, or follows a keybinding by listing its bindings at each click and running the Lua functions Hyprland runs for that key in its own Lua state, outside submaps and never the plugin's own drawer key, after checking every one is still there; an app gone, nothing bound or nothing picked opens the drawer; right-click then offers Open the app drawer; no Hyprland file is written), `look-custom` (Looks/LookField; default null, no control of its own: the Overview **Look** row saves the look keys there when leaving a Custom look, so Custom can be picked again; validated key by key). Their tests cover default resolution, ownership, theme choice, outline thresholds and scratchpad filtering.

Pressure keys remain validated and inert. The reveal delay supplies dwell timing, rather than pretending to measure pressure. Maximized clients use Hyprland fullscreen/maximized data, with a monitor-coverage heuristic for ordinary tiled clients, since Hyprland has no GNOME maximized flags. Global radius applies only to plugin surfaces. Blur and physical shortcuts are reviewer-managed.

Settings metadata is defined once per key in `settings/FormModel.js` / `Descriptors.js`. Each command/title pair shares one row editor, which writes both arrays together. The element editor exposes the five rendered elements, including `dateMenu` clock visibility; Activities, System menu and empty left/center boxes are omitted, with their saved entries and array positions preserved. Monitor selection, apply-to-all and persistent layout synchronization appear with two or more connected monitors. Plugin-only controls: Style / theme-bg-color, Style / icon-contrast-outline, Style / animate-appicon-hover-macos, Position / show-apps-hotkey, Position / show-apps-click, Fine-Tune / hide-omarchy-dock; Behavior / favorites is a read-only list. Overview / Look sets 19 existing appearance keys at once (`settings/Looks.js`: Windows, macOS, Custom) and is read back from them, not stored.
